# AI Decision Audit: From Predictive Model to Governed Decision

A small, fully-tested pipeline that trains classical ML and neural network
models on a real diagnostic dataset, then wraps the prediction in a
decision policy, a subgroup performance audit, and a latency/scalability
benchmark — built to demonstrate five specific AI/ML concepts end-to-end
rather than as an isolated model-fitting script.

## Why this project

Most "final project" ML repos stop at `model.fit()` and a single accuracy
number. That's a demo, not a system. This one treats the model as one
component in a pipeline that also has to be *governed* (decision policy),
*tested* (pytest + CI), *audited* (subgroup performance), and *benchmarked*
(latency) — which is closer to how this would actually need to work if it
shipped.

## What maps to what

| Module | Concept | Course module |
|---|---|---|
| `src/models.py` (Logistic Regression, Decision Tree) | Classical ML methods | *Machine Learning* |
| `src/models.py` (MLPClassifier) | Neural network training | *Neural Networks and Deep Learning* |
| `src/decision_layer.py` | Predictive AI → Decision-making AI | *AI Forms and Functions* |
| `src/fairness_audit.py` | Bias/fairness auditing, limitations | *Neural Networks and Deep Learning* (ethics), *Introduction to AI* |
| `src/capability_benchmark.py` | Speed, scalability, real-time adjustment | *The Intelligence Behind AI* |

## Dataset

Wisconsin Diagnostic Breast Cancer dataset (569 samples, 30 features),
shipped with scikit-learn — chosen because the binary target (malignant /
benign) maps naturally onto a real predictive-AI-informs-a-decision
scenario, not because it's a toy.

## Known limitation (stated up front, not hidden)

The fairness module is a **subgroup performance audit**, not a demographic
bias audit — this dataset carries no protected attributes (age, sex,
ethnicity), so a real fairness-by-demographic-group analysis isn't possible
on this data. The module instead checks whether error rates hold steady
across tumor-size quartiles, which is a legitimate technique but a narrower
claim. Treated as future work with a dataset that has demographic fields.

## Running it

```bash
pip install -r requirements.txt
python main.py          # trains models, runs audits, writes reports/
python -m pytest tests/ -v   # 11 tests: decision-layer contract,
                              # data-split integrity, model quality gates
```

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs the full test suite and a
pipeline smoke test on every push/PR to `main`.
